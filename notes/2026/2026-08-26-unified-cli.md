# ReverseHelper 统一 CLI、分析模式与版本发布

## 这次要解决的问题

希望安装项目后直接执行：

```powershell
reversehelper sample.exe
```

CLI 只负责接收路径、调度分析和展示用户可读错误，不能复制 PE 分析逻辑，也不能改变默认完整分析的结果。基础入口稳定后，继续加入 `--quick` 和 `--only`，用来减少初筛等待时间或聚焦单项输出。

## 先确认真实调用链

项目已经是 Python package，并且已有现代打包配置。实际调用链是：

```text
pyproject.toml 的 console script
  → reversehelper.cli:main
  → ReverseHelperAnalyzer.analyze
  → PE 解析、字符串、入口点、代码洞、密码学常量、加壳信号和风险计算
  → 终端展示与可选报告输出
```

因此不需要移动模块或新建第二套入口。`ReverseHelperAnalyzer.analyze()` 继续作为完整分析的唯一高层 API；以后增加模式时，CLI 可以在这一层上方做小范围分派。

## 最小修改

- 保留 `[project.scripts]` 中的 `reversehelper = "reversehelper.cli:main"`。
- 在帮助页加入基础命令、含空格路径和报告输出示例。
- 输入校验区分路径不存在、目录、非普通文件、读取失败和缺少 `MZ` 签名。
- 所有预期输入错误继续转换为 `AnalysisError`，CLI 返回非零状态，不输出 traceback。
- 新增 CLI 回归测试，不修改任何 PE 分析规则、阈值或报告字段。

## 模式边界

`--quick` 保留 PE 基础信息、节区、导入/导出、入口点和加壳/结构异常，跳过完整字符串、密码学常量与代码洞扫描。快速模式的风险分数不含字符串信号，因此明确显示为结构风险，不能与完整分数直接比较。

`--only strings` 只继续执行字符串提取和地址标注，`--only imports` 只展示导入函数，`--only anomaly` 只运行加壳与结构异常规则。三种单模块模式仍会完成 PE 合法性校验和解析依赖，但不会启动无关的高层扫描。

部分结果不适合直接套用完整报告模板：缺少某个字段表示模块未运行，不表示没有发现。因此 `--quick`、`--only` 与报告参数暂时互斥，完整报告仍由默认模式生成。

## 验证记录

在本地 Windows 虚拟环境中完成了以下只读验证：

- 可编辑安装成功，安装元数据中的命令入口为 `reversehelper.cli:main`。
- `reversehelper --help` 显示目标参数、描述和示例。
- 默认命令成功分析一个合法 Windows PE，未执行目标文件。
- 同一个 PE 放到含空格的临时路径后分析成功；临时副本随后删除。
- 不存在路径、目录、不可读文件和非 PE 文件均得到简洁错误，测试确认没有 traceback。
- `--quick` 和三个 `--only` 命令均使用合法 PE 完成只读实测。
- 相关测试确认快速模式没有生成 strings、crypto constants 或 code caves 结果。
- 38 项自动测试全部通过；源码包与 wheel 构建成功。

这里验证的是 CLI 调度、静态读取和错误边界，没有新增 Ghidra/x64dbg 动态观察，也没有使用或归档比赛私有样本。

## 版本发布约定

用户决定把模式扩展之前的仓库基线保留为 `v0.0.1`，把统一 CLI、输入校验、快速模式和单模块分析整理为 `v0.0.2`。两个版本都使用独立 Git 标签和 GitHub Release，README 中的版本号直接链接到对应源码 ZIP；发布新版本不会移动或删除旧标签。

项目原先存在历史标签 `v1.0.0`。为了不改写已经公开的历史，该标签继续保留；新的开发快照按用户指定的 `v0.0.x` 编号发布。`CHANGELOG.md` 记录真实功能边界，并明确快速风险分数不含字符串信号、部分模式不生成完整报告。

为 v0.0.1 补建 wheel 时，最初尝试 `build --no-isolation`，但当前虚拟环境无法直接导入 `setuptools.build_meta`，因此构建在读取后端阶段停止，没有生成错误版本的附件。改回 `pyproject.toml` 声明的隔离构建后，v0.0.1 的 wheel 和源码包均成功生成。这里的问题属于构建环境缺少后端，不是旧代码或 PE 分析逻辑失败。

最终发布附件改为两个独立源码 ZIP。它们直接由 `v0.0.1`、`v0.0.2` 标签通过 `git archive` 生成，只包含各标签实际跟踪的文件，并带有对应版本名的顶层目录；虚拟环境、构建缓存、本地样本、报告和 Git 历史不会进入压缩包。wheel 与源码包仍保留作本地构建验证，不作为主要下载入口。
