# ReverseHelper v0.1.0

> Local v0.1.0 release notes. The product is complete in this folder; no tag or GitHub Release has been created.

## New features

- x86/x64 Capstone disassembly bounded by PE raw section data.
- Basic direct/indirect CALL and JMP, Jcc, RET, target and RIP-relative pointer-slot reporting.
- Evidence-based Anti-Debug, Crypto, Validation and Input Findings.
- ReverseTarget ranking with local deduplication and `finding_ids` traceability.
- Suggested static questions, dynamic questions and unresolved observations.
- ASLR-safe x64dbg/x32dbg scripts using module-relative RVA expressions.
- Ghidra JSON import script with identity and address-range checks; comments are the default action.

## Improvements

- Existing crypto constant matches remain available and gain nearby instruction evidence where supported.
- MinGW-style one-hop import thunks and conservative IAT-to-register indirect calls can resolve to their actual caller.
- Capstone detail decoding and import-call resolution are shared across analyzers.
- Optional module failures are isolated and exposed through `analysis_warnings`.
- Markdown, JSON and HTML reports include Findings, ranked targets, analysis path and unresolved questions.

## Compatibility

- Existing default CLI behavior, legacy `--only` modes, report switches and exit-code meanings remain available.
- JSON Schema 1.2 appends fields without removing the v0.0.2 result fields.
- `--quick` remains a structural path and does not run instruction analyzers.
- Preferred VA is never exported as an ASLR-safe runtime address; debugger scripts use `module:$RVA`.

## Tests

- 136 automated tests passed on Windows Python 3.13.5 with 79% package coverage.
- x86/x64, raw section boundaries, truncated instructions, RIP-relative operands, evidence chains, ranking, reports and exporters are covered.
- Eight local synthetic/sample roles and two publicly licensed CTF binaries completed read-only static analysis without module warnings.
- The Ghidra importer passed automated logic tests. Ghidra and x64dbg were not installed on the local v0.1.0 validation host, so live import/debugger verification remains open.

## Known limitations

- Linear disassembly is not a full CFG and may include embedded data decoded as instructions.
- Compiler runtime code may yield genuine but low-value comparator or indirect-control-flow candidates.
- The tool does not recover complete call arguments, cross-function data flow, crypto buffers or branch success/failure semantics.
- Packed programs are not unpacked; useful instruction-level findings may be unavailable until after a separate unpacking workflow.
- Debugger breakpoints are suggestions, not guaranteed solution points.

Detailed measurements and sample hashes are in [Phase 6 validation](../phase6-validation.md).
