# 限制与可信边界

[简体中文](limitations.zh-CN.md) | [English](limitations.md)

- 本版本面向 Windows PE x86/x64 比赛目标。ELF、托管程序集和任意固件不在支持范围内。
- 分析是静态、有界且不区分路径的。工具不执行、不模拟、不脱壳、不进行符号求解，也不恢复运行时生成的代码。
- 加壳检测采用启发式规则。静态可见性受限时，脱壳前的字符串、排序和验证逻辑会明确降低可信度；应对获授权的脱壳后转储重新分析。
- 函数边界、输入来源追踪、验证逻辑、算法、控制流结构和语义名称均视为候选，除非对应证据明确支持更强结论。
- `result_status` 区分已解析/解码事实、待复查候选、可选建议、不可用模块和截断。“未知”就是未知，不能解读为安全、不存在或不成立。
- Quick 和 Deep 都有有限预算。`truncated_modules` 和警告表示覆盖不完整；Deep 增加广度，不增加确定性。
- Ghidra 导入器检查身份并默认添加注释/书签，但不能证明映射 RVA 的语义正确。
- 畸形输入返回简短错误。如果解析还能继续，可选模块的失败会被隔离并保存在 `analysis_warnings`。
- 在记录的协议获得真实参与者数据之前，不宣称任何真人 TTCF 测量结果。

## 不能因翻译而弱化的边界

- 严重混淆、间接控制流、多目标调用和运行时变换可能使静态追踪提前中断。类控制流平坦化结构只是候选，不证明存在平坦化，更不证明已还原控制流。
- 堆别名、复杂指针关系、跨调用别名及动态对象可能超出有界数据流模型。部分切片和可能的数据流片段不等于完整输入到验证逻辑路径。
- 公开基准仅有 40 个固定位置，31 个可用/冻结、9 个待补充；算法、控制流、语义类别的有效分母尤其小，不能推广为普遍准确率。既有数据见[基准文档](../benchmarks/README.md)。
- 本地化不会扩大 PE 支持范围，也不会增加新的分析规则。英文和中文共享 Ranking 2.2、Schema 1.5 与分析结果。
- 默认 Quick/Deep 的主要界面支持中文；开发者/debug 诊断、原始证据详情、旧单模块诊断及 x64dbg 脚本注释仍可能是英文。样本自身字符串始终原样保留。
- Windows 进程内重定向输出使用 UTF-8；原生控制台保留可输出中文的编码，不修改系统区域设置或控制台代码页。读取重定向文本的程序也必须使用匹配编码。
- 本机自动化验证不等同于独立干净 Windows 机器验证，也不等同于真实 Ghidra UI 的重复导入验证。实际执行范围见[本地化报告](simplified-chinese-localization-report.md)。
